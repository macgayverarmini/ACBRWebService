## 2024-06-24 - Concurrency and Hardcoded Logging Path via Global TextFile
**Vulnerability:** The route handling script (`routes/route.acbr.nfe.pas`) declared a global variable `var F: TextFile;` and used it within `try..except` blocks across concurrent request threads to write debug logs to a hardcoded Windows path (`C:\NFMonitor\src\bin\log_debug.txt`). This setup posed concurrency risks (race conditions between concurrent threads opening/writing/closing the same global variable) and potential Denial-of-Service (DoS), along with unintended path traversal and file creation issues when run on non-Windows environments.
**Learning:** Legacy debug blocks using global objects in concurrent frameworks (like Horse in Free Pascal) can inadvertently leak state and cause application crashes or insecure cross-thread logging behaviors. Hardcoded absolute Windows paths in such blocks further break execution safety on Linux or Docker.
**Prevention:** Avoid defining file descriptors or other stateful variables globally in web route units. Implement structured, thread-safe, and environment-configurable logging instead of writing directly to hardcoded files inside HTTP route implementations. Remove legacy debug/`AssignFile` statements altogether when shipping production code.
