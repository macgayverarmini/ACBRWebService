## 2025-02-25 - Avoid Global File Descriptors and Legacy Debug Logs in Web Routes
**Vulnerability:** A global `var F: TextFile;` was used alongside legacy `AssignFile`/`Append` debugging blocks writing to a hardcoded path (`C:\NFMonitor\src\bin\log_debug.txt`) within an active Horse web route (`routes/route.acbr.nfe.pas`). This creates a significant concurrency / DoS risk because multiple requests modifying the same global file descriptor can lead to access violations and application crashes. It also presents a path error in non-Windows environments and leaks sensitive control-flow behavior to a predictably named file.
**Learning:** Legacy Delphi/Free Pascal debugging code often relies on global file variables, which are fundamentally incompatible with asynchronous, highly concurrent web frameworks like Horse. Hardcoded Windows paths add a secondary layer of failure on Linux/Docker deployments.
**Prevention:** Remove all leftover debugging blocks before committing web routes. If logging is required, use proper framework-level logging mechanisms, local variables for file handling, or secure, configurable log file paths.
