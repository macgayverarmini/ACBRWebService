## 2024-06-06 - Concurrency DoS and Hardcoded Path via Global TextFile
**Vulnerability:** A global file descriptor `var F: TextFile;` was used in a route handler (`routes/route.acbr.nfe.pas`) along with hardcoded Windows file paths (`C:\NFMonitor\src\bin\log_debug.txt`) for debug logging.
**Learning:** In a web application handling concurrent requests (using the Horse framework), global file descriptors create a significant race condition. If multiple requests try to write simultaneously using the same file descriptor or hardcoded path, it can lead to file locking exceptions, data corruption, and potentially a Denial of Service (DoS) as the handler crashes. The hardcoded path also fails in environments where `C:\NFMonitor` doesn't exist, disclosing expected file structures or leading to runtime errors.
**Prevention:** Never use global variables for state or file operations within concurrent route handlers. Remove legacy debug file logging using hardcoded paths (`AssignFile`, `SaveToFile` to `C:\...`). If logging is necessary, use a proper thread-safe logging framework or configurable paths injected at runtime, isolated per request.
