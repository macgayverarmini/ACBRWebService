## 2024-06-23 - Optimizing stream operations and base64 conversions
**Learning:** In Lazarus/FPC, `TMemoryStream.Read` and intermediate byte arrays (`TBytes`) allocated via `TEncoding.UTF8` are inefficient compared to directly using `TStream.ReadBuffer` with native string types, which also avoids unnecessary string-to-bytes-to-string round-trips. Furthermore, redundant function evaluation is an issue when functions like `TEncoding.UTF8.GetString` and `base64.EncodeStringBase64` are called multiple times in arguments for procedures like `WriteBuffer` and `Length`.
**Action:** Replace `TBytes` usage with native string reading (`ReadBuffer(str[1], AStream.Size)`) after checking stream size (> 0). Cache results of expensive encoding operations instead of redundantly evaluating them in inline arguments.
