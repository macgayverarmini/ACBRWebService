## 2026-06-10 - Avoid Intermediate TBytes Allocations and Redundant Function Calls in Pascal Streams
**Learning:** Using `TEncoding.UTF8.GetBytes/GetString` for simple stream reading and string base64 conversion in Pascal introduces unnecessary intermediate `TBytes` array allocations. Furthermore, passing an inline function call multiple times as arguments to a procedure (e.g., `Result.WriteBuffer(base64.EncodeStringBase64(...)[1], Length(base64.EncodeStringBase64(...)))`) causes the compiler to evaluate the expensive encoding function redundantly (O(N) operation done twice).
**Action:** When reading from `TMemoryStream` directly into strings, initialize the string and use `AStream.ReadBuffer(str[1], AStream.Size)` instead of a byte array to improve performance. For function calls used multiple times in procedural arguments, cache the result in a local variable before passing it to avoid double execution.
