## 2024-03-20 - Stream base64 conversions string handling and redundant evaluation optimizations
**Learning:** In Free Pascal/Delphi, when manipulating streams of base64 strings, allocating `TBytes` arrays via `TEncoding.UTF8` for conversions to/from streams adds unnecessary memory allocations, intermediate copies and CPU overhead compared to reading directly into native strings (`ReadBuffer(str[1], size)`). Furthermore, passing inline calls to expensive functions (like `base64.EncodeStringBase64`) twice as arguments in a procedure (e.g. `Result.WriteBuffer(func()[1], Length(func()))`) causes the compiler to evaluate the function redundantly.
**Action:** When working with streams of base64 content or string encoding, read/write directly using native strings with `TStream.ReadBuffer` and `TStream.WriteBuffer`. Always store the result of an expensive function call in a local variable before using it multiple times in a procedure call.
