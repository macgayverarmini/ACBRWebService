## 2024-05-24 - Avoid intermediate byte arrays in stream manipulations
**Learning:** In Lazarus/FPC stream manipulations, converting native string payloads through `TEncoding.UTF8.GetBytes` to obtain intermediate `TBytes` arrays incurs unnecessary memory allocation and performance overhead compared to reading/writing natively using the string index directly (e.g., `AStream.ReadBuffer(str[1], AStream.Size)`). Similarly, redundant inline function evaluation can dramatically multiply execution time, especially with relatively expensive operations like base64 encoding.
**Action:** When manipulating streams mapped to string-based contents or decoding/encoding structures, always avoid intermediate byte arrays by passing native strings directly to `ReadBuffer`/`WriteBuffer`, and evaluate potentially expensive functions once, assigning results to local variables rather than re-computing them inline.
