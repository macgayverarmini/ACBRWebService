## 2024-06-13 - Avoid redundant evaluations and intermediate encoding arrays in stream manipulation
**Learning:** Calling the same inline function multiple times as arguments (e.g. `Length(EncodeStringBase64(...))` and `WriteBuffer(EncodeStringBase64(...)[1], ...)`) causes redundant evaluation of the expensive Base64 encoding. Also, converting native strings to `TBytes` arrays via `TEncoding.UTF8.GetBytes` and then back to strings via `TEncoding.UTF8.GetString` is unnecessary overhead when `ReadBuffer` and `WriteBuffer` can work directly with string characters via index `[1]`.
**Action:** Store results of expensive operations (like `EncodeStringBase64`) in a local variable before using them multiple times. Pass strings directly to stream read/write functions (e.g. `AStream.ReadBuffer(str[1], AStream.Size)`) rather than allocating intermediate byte arrays.
