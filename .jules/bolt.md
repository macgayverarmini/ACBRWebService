## 2024-05-09 - Avoid Intermediate Byte Arrays and Redundant Function Calls in Stream Formatting
**Learning:** In Lazarus/FPC, allocating intermediate `TBytes` arrays via `TEncoding.UTF8` for reading streams into strings introduces unnecessary memory allocations and performance overhead. Furthermore, passing an inline string-returning function call twice into `WriteBuffer(Func()[1], Length(Func()))` causes redundant evaluation of potentially expensive operations (like Base64 encoding).
**Action:** Use native string types directly with `TMemoryStream.ReadBuffer` and `WriteBuffer` (e.g., `AStream.ReadBuffer(str[1], AStream.Size)`), combined with checking `Length(str) > 0` before indexing. Always store the result of expensive inline computations in a local variable before using them as size boundaries and buffer pointers.
