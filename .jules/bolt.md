## 2025-01-22 - Optimize Stream Tools Base64 Encoding and Stream Allocation
**Learning:** In Lazarus/FPC, passing the same inline function call multiple times as arguments to a procedure (e.g., `WriteBuffer(Func()[1], Length(Func()))`) causes the compiler to evaluate the function redundantly. Furthermore, allocating intermediate `TBytes` arrays via `TEncoding.UTF8` for stream reads/writes creates unnecessary memory overhead compared to using native `string` types directly with `TStream.ReadBuffer` and `WriteBuffer`.
**Action:** Store the result of expensive computations in a local variable before use in procedure arguments. When expecting exact byte sizes for stream operations, natively index string parameters directly (e.g., `AStream.ReadBuffer(str[1], AStream.Size)`) after ensuring they are not empty, avoiding memory leaks, out-of-bounds exceptions, and redundant `TBytes` creation.
