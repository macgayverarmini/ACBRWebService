## 2024-05-24 - Stream tools intermediate allocation bottleneck
**Learning:** In Lazarus/FPC, `TEncoding.UTF8.GetBytes` and `TEncoding.UTF8.GetString` allocate intermediate `TBytes` arrays. When reading from or writing to `TMemoryStream`s, reading/writing directly to native strings (using `ReadBuffer(str[1], Size)`) is significantly faster and uses less memory. Furthermore, passing an expensive inline function call twice to a procedure (e.g. `Result.WriteBuffer(Func()[1], Length(Func()))`) causes redundant evaluation.
**Action:** Always read/write directly to native string memory when dealing with `TMemoryStream`s, bypassing `TBytes` and `TEncoding` when string content matches native types. Always store expensive function calls in local variables if the result is needed multiple times as function arguments.
