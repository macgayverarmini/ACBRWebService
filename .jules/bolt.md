## 2024-05-24 - Redundant function evaluation in Pascal WriteBuffer
**Learning:** In Free Pascal/Lazarus, passing the result of an inline function call directly to both `WriteBuffer`'s pointer and length parameters (e.g., `Result.WriteBuffer(Func()[1], Length(Func()))`) causes the compiler to evaluate the function twice. Additionally, translating strings to bytes (`TEncoding.UTF8.GetBytes`) and back again to read from or write to streams is inefficient. Native string types can be used directly with `TMemoryStream.ReadBuffer` and `WriteBuffer` (e.g., `AStream.ReadBuffer(str[1], AStream.Size)`), avoiding unnecessary memory allocations and garbage collection for `TBytes` arrays.
**Action:** When writing to streams from function results, always store the result in a local variable first (e.g., `LBase64 := base64.EncodeStringBase64(AString);`). Use direct string pointer access (`str[1]`) with `ReadBuffer`/`WriteBuffer` and `SetLength`, ensuring you check that the stream size or string length is > 0 before accessing the first index to prevent out-of-bounds exceptions.
